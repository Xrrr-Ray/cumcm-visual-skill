# 国赛论文单页反馈决策回路评测

`case_id`: `paper-visual-feedback-loop-003`

## 目的

比较两个现有网页 PPT Skill 将固定质量检测逻辑制作成论文单页反馈决策回路的能力，重点检查条件分支、两条回边、语义标签和论文截图模式。本案例不是整份 PPT，也不测试论文正文生成。

参考图只用于阶段分区、决策分支、跨区反馈路径和留白规律的视觉启发。不得嵌入、描摹参考图，也不得复制其中的文字、颜色细节或像素布局。

## 固定标题

`产品批次质量检测与闭环处置流程`

## 结构真值

### G1：检测判定

- N1 `待检批次`：新到货产品
- N2 `初次抽检`：按基础比例取样
- N3 `初检判定`：是否达到放行阈值；决策节点
- N4 `扩大抽检`：增加样本确认风险
- N5 `复检判定`：合格 / 可返工 / 不可返工；决策节点

### G2：处置决策

- N6 `批次放行`：进入交付环节
- N7 `返工处理`：纠正可修复缺陷
- N8 `返工复检`：验证整改效果
- N9 `报废隔离`：阻断不合格品

### G3：反馈更新

- N10 `规则更新`：更新阈值与抽检比例

### 固定有向连接

1. E01：N1 → N2，`flow`
2. E02：N2 → N3，`flow`
3. E03：N3 → N6，`pass`，标签 `合格`
4. E04：N3 → N4，`reject`，标签 `不合格`
5. E05：N4 → N5，`flow`
6. E06：N5 → N6，`pass`，标签 `合格`
7. E07：N5 → N7，`reject`，标签 `可返工`
8. E08：N5 → N9，`reject`，标签 `不可返工`
9. E09：N7 → N8，`flow`
10. E10：N8 → N5，`feedback`，标签 `返工后复检`
11. E11：N6 → N10，`flow`，标签 `结果归档`
12. E12：N9 → N10，`flow`，标签 `缺陷归档`
13. E13：N10 → N2，`feedback`，标签 `阈值更新`

不得增加、删除、反转或改写节点、分组、连接、连接类型和连接标签。

## 机器可核验标记

- 每个可见节点的主容器必须写 `data-node-id` 和 `data-group`。节点内部承载主标题的可见 HTML 元素必须写 `data-node-title`，属性值为结构规范中的 `label`；承载说明的可见 HTML 元素必须写 `data-node-detail`，属性值为结构规范中的 `detail`。每个节点各恰好一个标题标记和一个说明标记。
- 每个可见分组容器必须写 `data-group-id="G1"` 至 `data-group-id="G3"`。
- 每条可见连接必须写唯一的 `data-edge-id="E01"` 至 `data-edge-id="E13"`，以及对应的 `data-edge-from`、`data-edge-to`、`data-edge-kind`；规范中带 `label` 的边还必须在连接元素上写相同文字的 `data-edge-label`。
- 每个有标签的连接必须将可见标签写成 HTML，并在标签元素上写 `data-edge-label-for`，其值为对应的边 ID；SVG 不得承载标签文字。
- SVG 只能绘制线、箭头和几何图形；所有可见文字必须使用 HTML。

## 共同视觉要求

- 只生成恰好一页 16:9 HTML 图示，白色或近白色背景，不制作封面、目录或收尾页。
- 主流程从左至右，反馈线从节点区外侧绕回；N3 与 N5 必须在视觉上可识别为决策节点。
- 页面标题和节点主标题在 1920×1080 视口中均不得低于 32 px；节点说明和连接标签不得低于 28 px。
- `pass` 使用绿色实线并显示文字，`reject` 使用橙红实线并显示文字，`feedback` 使用青色或蓝色虚线并显示文字；不得只靠颜色表达分支含义。
- 至少清晰显示 N8 → N5 和 N10 → N2 两条回边，回边不得穿过节点或文字。
- 不得出现可见页码、翻页提示、键盘提示、导航按钮、进度条或网页控制栏；键盘导航等运行能力可保留，但控件必须隐藏。
- 使用克制的学术配色，不使用照片、emoji、渐变、重阴影或装饰性插画。
- 不得编造公式、数据、模型、结论或引用。
- 输出必须能由 Chrome 真实加载并生成 1920×1080 PNG；PNG 是评测器产生的派生验证产物，不得伪造。
